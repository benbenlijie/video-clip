# Wayne CASE 01 真实 MVP 设计

## 意图

把现有 Wayne 工作流原型变成可公网访问的单机真实 MVP，完成“上传一条口播 → 读取媒体 → 生成剪辑计划 → 人工批注 → FFmpeg 生成主片与 Shorts → 下载产物”的可恢复闭环。

## 目标

- 项目和任务状态在服务重启后仍可恢复。
- 上传视频使用真实 FFprobe 探测；原始视频不被覆盖。
- 转录优先使用已配置的火山引擎，腾讯云作为备用；没有有效凭证时明确返回 `needs_input`。
- Claude 生成结构化剪辑计划；计划包含保留、收紧、删除区间和 Shorts 区间。
- 批注被保存并参与一次受限的第二版计划。
- FFmpeg 根据剪辑计划输出主片、5 条竖屏 Shorts、SRT、cut-list JSON、QC JSON 和命令日志。
- 前端显示真实状态、真实媒体播放器和真实下载链接；刷新页面可通过项目 ID 恢复。

## 非目标

- 多用户协作、权限、计费、自动发布平台。
- 复杂多机位、3D 特效、云队列和对象存储。
- 把无凭证或失败任务伪装成成功。

## 方案

1. 单机 Node API + 磁盘 JSON/媒体目录 + FFmpeg（采用）。改动集中，能直接接入当前公网反代。
2. OpenChatCut MCP 编排。能力更宽，但会引入会话、异步工具循环和 AGPL 商用边界，不适合首个公网闭环。
3. 云原生存储/队列/渲染 Worker。并发更强，但需要额外基础设施配置，超出当前 MVP 的验证范围。

## 架构与数据流

`POST /api/projects` 创建项目并写入 `project.json`；`POST /input` 保存原始媒体并探测；`POST /advance` 驱动有限状态机。转录结果、剪辑计划和批注均写入项目目录。`POST /render` 根据已确认计划调用 FFmpeg，产物写入 `artifacts/`，完成后生成 QC。项目 API 返回相对下载 URL，静态媒体路由只允许访问项目目录内文件。

计划生成使用服务端 Anthropic 配置；若模型响应无法解析为合法 JSON，任务进入 `needs_input`，而不是生成假计划。为了让无 Claude 的开发环境可运行，API 仍可完成探测和产物路由，但不会跳过计划确认。

## 错误与恢复

- 每个阶段最多一次实际执行；阶段失败记录错误、时间和日志。
- 服务启动时扫描 `storage/*/project.json` 恢复项目索引。
- 任何渲染失败保留输入、计划和 FFmpeg stderr，状态为 `failed`。
- 下载路由拒绝路径穿越和项目外文件。

## 验证

- `npm run typecheck` 与 `npm run build`。
- 用仓库内测试视频创建项目，验证上传、FFprobe、持久化重启、计划/批注接口、FFmpeg 主片与 Shorts、QC 和下载。
- 通过公网域名检查页面、健康接口和一个真实项目的恢复路径；凭证未配置时验证错误状态清晰可见。
