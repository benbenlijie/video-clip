# 统一视频审核与修改工作台

## 目标与已选方案

用户已选择“统一审核页和修改流程”，并进一步明确 Remotion 应作为主流程的制作工具，实际参与统一预览和正式成片。日常操作收敛为：上传视频 → 自动制作 → 看视频并提出修改 → 确认导出。用户始终能知道自己在看哪个版本，以及当前需要做什么。

考虑过的两种方案：只隐藏 Remotion 等技术入口，改动较小，但仍保留批注与对话两套修改路径；统一审核和修改页面，涉及页面组织与状态展示，但能消除重复入口。采用用户选定的第二种方案。

沿用当前 React 页面和视觉风格，不另建编辑器。Claude 继续负责剪辑决策与工具操作；Remotion 接入主视频制作的具体设计见 `2026-11-04-remotion-main-workflow-design.md`。

## 页面与操作

### 1. 上传与制作

- 准备页保留视频、剪辑目标及可选素材，主操作为“开始制作”。
- 制作页显示人能理解的阶段，如“识别内容”“制作草剪”“检查视频”，详细工具活动默认收起。
- 进度根据真实任务状态展示，不把页面序号换算成制作百分比；失败时停止显示忙碌或“已完成当前耗时任务”等矛盾提示。
- 继续保留刷新恢复、项目历史和上传中断恢复。

### 2. 一个审核工作台

- 合并当前 `review` 和 `conversation` 页面。取消独立的“对话调整”流程步骤。
- 顶部显示当前项目、版本和明确状态，如“草剪 v2 · 等待确认”或“v2 · 正在导出”。
- 桌面优先并排展示视频和修改对话；手机依次展示视频、待处理提示、字幕校对、修改框和导出操作。
- 每次只显示一个主视频播放器，默认显示最新版本；该版本已有正式成片时显示成片，否则显示草剪。
- “最新版本”以已成功登记的预览或成片为准；新一轮处理中或失败时，旧版播放器仍标记其真实版本。某版本没有成片时不得取上一版成片来充当该版本结果。
- 历史版本通过下拉菜单查看，明确标记“正在查看历史版本”；回到最新版本后才能发送修改、保存字幕或导出，避免误以为正在修改旧版。
- 只保留一个修改输入框和“发送修改”按钮。可将播放器当前时间填入修改范围，时间范围为选填项。
- 修改时间使用当前视频的播放时间；明确绑定其版本。视频时长与时间轴使用当前产物时长，不能用未剪切原片的时长。交给 Claude 的指令需说明时码属于当前预览。
- 发送后留在当前工作台，显示“正在生成新版本”，保留上一版可播放视频。成功后显示最新版本；失败时保留输入、错误信息与上一版。
- 旧版项目批注保留在折叠记录中；已有未执行批注可载入统一修改框，由用户检查后发送，不静默执行或重复发送。
- 详细剪辑计划和原始工具日志折叠为“制作详情”，不占用主操作区。

### 3. 字幕与导出

- 字幕有待确认内容时，播放器附近显示“还有 N 处字幕需要确认”，并可直接展开对应句子的原音与编辑框。
- 正常情况下字幕编辑默认收起；Whisper 不可用的项目仍保留逐句人工确认要求，不能为了简化页面跳过校对。
- 字幕草稿未保存时，清楚提示先保存；已保存文字尚未进入预览时，主操作变为“更新字幕预览”。不在后台自动发起收费的 AI 请求。
- 当前项目无待确认字幕、无未保存修改、预览文字已更新且任务空闲时，主操作才为“确认并导出”。
- 修改框的提交是独立明确动作；导出区根据状态只显示一个主操作，不同时堆放重做、继续、确认等含义接近的按钮。
- 导出时保留当前视频和修改记录，显示实际导出状态。成功后突出“下载成片”，字幕、Shorts 和工程文件放进“更多下载”。
- 导出后仍可返回同一个工作台提出修改；修改产生的新版本需要重新确认与导出，不把旧版正式成片标成新版结果。

### 4. 高级功能与错误

- 移除主界面的“生成 Remotion 对照”按钮，不再在新任务中自动制作独立对照视频。Remotion 在后台实际制作主视频使用的动效；用户只审核统一预览。旧对照产物保留在历史工程详情，避免与主视频混淆。
- OpenChatCut 连接检查、服务配置、模型和工具名称集中到高级信息；保留当前本机访问限制及授权提示。
- 错误优先说明任务结果及下一步。技术原因放进可展开详情，不能一律将 `needs_input` 显示为“需要配置”。
- 已有可用版本时展示该版本并说明新一轮失败；仍无预览时展示继续本项目的入口，不要求重新上传。
- 前端不把模型的完成描述当作成功依据，依据项目状态和已登记产物决定视频与下载是否可用。

## 实施边界

- 界面主要修改 `portal/src/App.tsx` 和 `portal/src/styles.css`；按需要抽出少量共享的版本选择及界面状态函数，以便验证映射规则。Remotion 主流程接入另按配套设计修改相关工具、合成与校验。
- 复用现有字幕确认、对话修改和导出接口。若端到端检查发现界面必需的接口状态缺陷，仅做直接相关修正并保留原数据结构。
- 保留历史工程、原视频、字幕源稿、旧版本及现有未提交修复；不做数据库迁移、分支操作、提交或推送。
- 验证期间不发送真实 Claude、云端 ASR 或素材搜索请求；使用只读实际项目检查和隔离测试数据。不得为了浏览器验收修改真实项目状态。
- Remotion 实际参与统一草剪和正式成片，不新增用户选择引擎的步骤。保留字幕、音画同步、来源许可和成片 QC 门禁，并增加主视频动效合成证据检查。

## 验收

- 用户无需理解工具名即可完成上传、审核、提出修改和导出；不再出现独立批注提交和独立对话页两套入口。
- 在草剪就绪、修改中、修改失败、字幕待确认、字幕预览过期、导出中和导出完成状态下，当前视频、提示与可用操作一致。
- 最新版本与历史版本明确区分；失败后旧版可播放，刷新后可恢复到真实状态。
- 未确认字幕、未保存字幕及过期预览均不能导出；正式成片下载绑定正确版本。
- 桌面与手机均可读、可操作，单页不横向溢出；真实浏览器验证播放器、版本切换、展开校对和修改框。
- `npm run typecheck`、`npm run build`、相关验证及完整 `npm run verify` 通过；记录未能验证的真实收费操作。
