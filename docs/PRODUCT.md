# 产品定位与目标

## 一句话定位

本产品是一个**基于真实成功案例的视频制作工作流复制器**：它把 Claude Opus 5.5 的视频后期编排能力、成熟的媒体工具和可复用的创作者风格，包装成可选择、可检查、可恢复、可重复执行的工作流，让创作者快速复现经过验证的成片路径。

## 我们解决的问题

创作者通常不是缺少一个“会调用模型的聊天框”，而是缺少一条稳定的生产路径：不知道先转录还是先剪辑，不知道如何把个人风格写成规则，不知道何时需要预览和人工确认，也难以保留可编辑工程和回退产物。

产品将成功案例中的隐性经验显式化：

- 先盘点素材和转录，再生成剪辑计划；
- 用 cut list、时间戳和 storyboard 作为中间产物；
- 先做静态或低成本预览，再做完整渲染；
- 在关键阶段让用户确认，而不是让 Claude 无限探索；
- 同时保存 MP4、字幕、源码、命令、QC 日志和可编辑工程。

## 首批用户与场景

首批用户是制作 Vibe coding、产品演示和知识型口播内容的个人创作者及小型内容团队。

第一阶段以调研中的 **Wayne St Ledger / Claude Video Editing / OPUS 5.5 / CASE 01** 为唯一复现目标，先把一条成功工作流做成可执行产品。首版入口不是泛化的 AI 剪辑器，而是 Wayne 方法的工作流卡片。

首版工作流入口：

1. **Wayne Video Editing / 一条录制变五条内容**：转录、删除停顿和重录、语音同步视觉元素、浏览器预览、时间戳批注、最终渲染和 Shorts 拆分。

后续再扩展：

- **Vibe coding 录屏 → 教程视频**：识别代码/界面区域、局部放大、关键操作高亮、字幕和章节。
- **脚本/参考图 → 动效视频**：参考图、静态 storyboard、短动效预览、Remotion/HyperFrames 完整渲染。

后续再扩展个人频道自动化、可编辑后期和 Resolve/FCPXML 等复杂时间线工作流。

## 核心产品原则

1. **工作流优先**：用户先选择目标结果，再进入对应配方；不以空白聊天框作为主入口。
2. **阶段化执行**：Claude 必须按 `inspect → transcribe → plan → storyboard → preview → review → render → qc → export` 推进。
3. **人机共同验收**：模型负责分析、编排和迭代；用户负责关键取舍和最终审美确认。
4. **证据透明**：案例和模板标注 A/B/C 证据等级，不承诺播放量或完全替代人工。
5. **可回退交付**：保留原始素材、转录、cut list、源码、命令、预览、最终视频、QC 日志和可编辑工程。

## 业务成功标准

MVP 不以“模型调用成功”作为成功，而以可复现的生产结果为准：

- 用户能在 5 分钟内选择并启动一个明确工作流；
- 60–90 秒测试素材能生成可审阅的转录、cut list 和 storyboard；
- 用户批注后，Claude 能在限定步骤内生成第二版；
- 至少一种工作流能稳定导出可播放 MP4 和完整过程产物；
- 用户可以恢复、重做或跳过一个阶段，而不必重新开始整个任务。

## 明确不承诺

- 不承诺自动获得高播放量；
- 不把 Claude 描述成独立替代 Premiere、Final Cut Pro 或 DaVinci Resolve；
- 不把外部转录、配音、音乐、素材库或视频模型的能力归因于 Claude；
- 不在首版追求多机位纪录片、摄影级广告和无人审片交付。
