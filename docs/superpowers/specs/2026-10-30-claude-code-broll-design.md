# Claude Code 自主搜索并剪入 B-roll

## 意图

让 Claude Code / Opus 5.5 根据真实口播判断是否需要 B-roll；需要时，它负责提出搜索意图、审看候选、自动下载合适素材、安排源时间与成片插入位置，并把 B-roll 纳入粗剪预览。用户已选择自动下载并纳入预览，不需要逐个候选暂停等待授权确认。

## 当前问题

- 页面搜索只把候选放进临时 React 状态，项目没有可导入候选的持久流程；最新样例项目保存的 B-roll 素材数和插入点数均为 0。
- Claude Code 编辑会话只有读写文件、看帧和断网媒体命令，没有搜索或下载 MCP 工具；启动时只能复制此前已上传素材。
- `validateEditPlan(..., {allowCustomVisualEvents:true})` 返回时把 `brollEvents` 写死为 `[]`，即使代理提供了有效插入计划也会丢失。
- 旧 FFmpeg 渲染器能执行 `project.brollAssets` 与 `plan.brollEvents` 的组合；新 Claude Code 工作流还没有要求 manifest 记录或核验实际使用的 B-roll。

## 方案选择

1. **逐候选人工确认再下载。** 许可风险最低，但每次搜索都会暂停编辑会话，并把“是否使用”的决策重新交给用户；与本次选择不符。
2. **Claude 自动从已配置的 Pexels/Pixabay 搜索、选择并下载。** 用户已选择此方式。搜索工具限制在这两个来源，不提供通用网络/URL 下载能力；完整记录来源与授权信息，下载后先进入低清预览，成片仍保留人工审看阶段。

## 设计

1. Opus 先查看转录与原片，在剪辑计划中选择零至三个值得补画面的时点；不适合时不搜索。搜索词由当前 Claude Code 会话直接生成，不再启动嵌套 Claude Messages 请求。
2. 专用 MCP `search_broll` 只调用服务端已配置的 Pexels/Pixabay API，限制查询数、返回数、时长和文件大小，并返回候选 ID、缩略图、来源页、作者与许可信息。Claude 通过图像输入查看缩略图，再以候选 ID 调用 `download_broll`；API 密钥及网络请求只存在于专用 MCP 进程，FFmpeg/Python/Node 媒体执行器继续断网。
3. 下载器只允许候选搜索记录中的来源及 CDN 主机，逐次校验重定向目标、响应大小、视频容器、媒体时长和画幅；文件保存于该项目的 Claude Code 工程。保存 provider、provider ID、source URL、作者、license URL/name、下载时间、SHA-256 与文件路径。缓存搜索响应，不把 license 声明扩大成未经验证的权利保证。
4. Opus 写带 `assetId`、源时间、原片插入时间及持续时间的 `brollEvents`，将已下载素材用于自己的剪辑脚本，在预览中选画中画或切入方式。保留口播音轨，默认丢弃 B-roll 原始音频；不合适、下载失败或授权信息缺失时跳过并说明，不伪造素材。
5. 工程 manifest 声明下载资产和使用事件。服务端将下载素材与来源记录持久化到项目，验证每个使用 ID 都有对应文件和许可元数据、时间戳位于保留剪辑区间，并要求 Claude 至少查看每个 B-roll 区间的一张最终预览帧。QC 分别报告候选数、下载数、计划数、实际使用数、来源和失败项；未使用的下载素材显示为“已下载，未剪入”，不算使用成功。
6. 用户审看完整低清预览和来源记录后再批注或要求调整；批准后，Opus 在同一工程中渲染终稿并再次审看插入点。无合适素材时主片照常完成，B-roll 数为零是有效结果。

## 边界与验收

- 网络出口只有素材搜索与特定候选下载 MCP 工具；媒体 shell 保持无外网，搜索和下载都不能接收任意 URL。
- 搜索有界：每个剪辑版本最多 3 个意图、每个意图最多 2 个查询、每个查询最多 8 个候选；单素材默认不超过 100 MB，超过即跳过并记录。
- 用 mock 响应验证 provider 限制、候选 ID 绑定、恶意重定向/超大文件拒绝、缓存、授权元数据持久化和许可证缺失处理；真实样例验证 Claude 自主选择搜索或跳过，下载后在正确时间点插入，并在预览/终稿中逐个复核。
- 本次不实现泛化网页爬虫、任意 URL 导入或自动购买素材；不绕过用户已选的人工终稿审看。

## 需要审批的事项

本设计按照“Claude 可自动从已配置的 Pexels/Pixabay 下载并放入预览，不逐候选询问；保存来源和许可记录；用户仍审看预览后再批准终稿”执行。
