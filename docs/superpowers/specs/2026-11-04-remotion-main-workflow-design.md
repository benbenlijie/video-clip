# Remotion 接入主剪辑流程

## 用户已明确的目标

Remotion 是主流程的制作工具，其输出应真实进入统一草剪和最终成片。用户只审核当前版本的一个视频，不需要理解渲染器名称或选择两条路线。此设计与 `2026-11-04-unified-review-workspace-design.md` 配套实施。

## 方案选择

采用“Remotion 生成透明动效层，FFmpeg 合成到实际剪辑视频”的接法。现有运行时已支持本地 ProRes 4444 透明输出，可以复用。Claude 继续决定保留哪些片段、怎样安排字幕和视觉效果，并操作受限工具完成工程。

考虑过的另一种做法是由 Remotion 承担全部视频裁剪、素材解码、声音混合和输出。这会重复现有 FFmpeg 能力，并扩大本轮改动，因此本轮采用透明动效层的接法。

## 单一主流程

1. 提取音频、并行识别并校对字幕，沿用已确认的流程。
2. Claude 生成剪辑计划，通过 FFmpeg 制作实际裁剪后的基础视频，包含批准的画面切换和素材，保留音轨。
3. 根据同一剪辑结果，确定动效在成片中的实际时间与画幅。
4. Remotion 本地渲染片头标题、重点强调和结尾等已安排的动效层。
5. 受限合成工具把动效、基础视频和已校对字幕合成一个预览或正式成片，保留基础音轨和既有声音处理。
6. Claude 审查这个实际合成视频的画面；服务端独立校验文字、时长、音画同步、黑帧与合成记录。
7. 用户在统一工作台审核、提出修改或确认导出。修改后沿用同一流程产生新版本。

预览和正式导出可以有不同分辨率与编码质量，但必须使用同一版本的剪辑计划、字幕、动效文案与时间安排。正式导出按目标尺寸重渲染动效，不把低清样片直接当作正式成片。

## 时间轴与字幕

- 原片时间与剪辑后时间分开记录。每个实际保留片段都记录源起止时间及对应输出起止时间，顺序与 FFmpeg 实际执行的裁剪一致；使用帧对齐后的时间，不能只按原片时长或计划备注推测。
- 复用能验证的已有 `timeline.json` 裁剪映射；没有映射的工程由 Claude 在制作基础视频时明确导出映射。合成工具拒绝缺失、倒序、重叠或与基础视频时长不一致的映射。
- 动效先与实际保留片段求交集，再转换到输出时间。完全被剪掉的动效不渲染；跨多个保留片段的动效有确定的拆分和出现顺序，不能在删除区间继续播放。
- 合成前校验映射的输出时长、基础视频视频流时长和实际画幅；正常帧取整只允许一个输出帧的误差，音频编码尾部仍沿用音画同步容差。
- 初始支持范围明确为标题、重点和结尾动效；未知事件类型报出具体原因，不将未实现事件默默当作已完成。
- 字幕以已校对稿为准。保留现有“动效逐字显示的词可替代重复字幕”的显式覆盖记录；适配 Remotion 时同样验证实际输入文字及时间，不能把概述当逐字字幕。

## 工具与真实合成证据

- 在现有受限媒体 MCP 中提供主视频合成工具，输入限于当前工作区中的基础视频、字幕与明确的目标阶段，读取当前已验证剪辑计划和裁剪映射。不接收远程 URL 或任意 React 代码，不读取用户密钥。
- 主工具统一完成 Remotion 渲染和 FFmpeg 合成。由工具生成输入/输出及透明层哈希、剪辑映射、执行事件和渲染参数记录，避免仅凭模型声称已合成判定成功。
- 原透明层不再像对照工具那样渲染后立即删除；与本次动效输入、可复现模板/源码、工具记录一起保存在版本化工程中。旧结果不覆盖。
- 透明度检查在实际动效出现的时点取样，同时检查透明背景；不能只抽最初几帧，误拒绝稍后才出现标题的合法工程。
- 完成校验须将工具输出哈希绑定到 `manifest.main`，并验证阶段、字幕、计划、基础视频、裁剪映射、目标尺寸和动效哈希一致。不能拿原片上的动效对照、另一次工具结果或旧版动效证明本轮主视频已完成。
- 主视频需有覆盖关键事件的真实审片帧；重新渲染后重新审片，不复用旧视频的帧哈希。
- 修改剪辑、字幕、动效或尺寸后，原结果视为过期。允许缓存的前提是全部关联输入哈希相同。

## Remotion 与现有工具的分工

- Remotion 作为新任务标准标题、强调及结尾动效的默认制作工具，最终结果合成进主视频。
- HyperFrames 保留为现有工程兼容和复杂自定义动效能力，不再要求每个任务同时制作两套动效；同一个视觉事件只能由一个明确的工具负责，避免重复叠加。
- 不静默改写旧工程。旧工程继续按其已保存的源文件与合成方式修订；新建工程采用本设计。将旧工程转为 Remotion 的操作另作显式任务。
- 为新工程持久化主合成流程版本，并同步到工作区 brief、manifest 与合成记录；缺少新标记的旧工程维持原模式。刷新和重启后仍按工程自己的模式执行，不能仅用服务启动时的默认配置区分。
- Remotion 失败或缺失时保留上个可用视频，报告本轮制作未完成，允许重试。不能悄悄丢弃已安排的动效或改用另一套效果后仍标记完成。
- OpenChatCut 与 Motion Canvas 的既有边界不扩大；本轮不再接入其他引擎。

## 用户界面

- 移除新任务“生成 Remotion 对照”的必经操作及独立视频；原自动对照调用从 Claude 指令中撤下。
- 普通用户看到“生成预览”“更新预览”“确认并导出”等任务操作，以及一个当前版本播放器。
- 模型、渲染器、透明层、工程文件和执行记录放入制作详情。历史对照文件保留在工程历史，不标记为新版主视频。
- 界面与主流程一起验收，不能仅隐藏入口就宣称 Remotion 已进入主成片。

## 免费使用与验证边界

- 沿用已安装的 Remotion 4.0.539、本地浏览器和 FFmpeg；不引入云渲染、不升级核心依赖、不新增全局安装。继续保留现有免费使用资格与许可记录，不扩大为对所有商业场景免费的承诺。
- Remotion 本身的本地渲染不新增逐次云 API 请求；Claude 与现有云 ASR 的原有费用和会话预算保持明确，不将整个项目描述为零费用。
- 技术集成验证使用隔离工程和本地素材，不调用真实 Claude、云 ASR 或素材搜索；验证真实工具渲染、合成、登记、主视频抽帧与 HTTP 读取。工具与费用无关的模拟只用于触发界面状态，不能冒充真实渲染证据。
- 不重跑现有用户项目、不覆盖原始视频或已交付预览。用用户样片做新一轮 Claude 实测或重启线上服务时，先说明具体范围并确认已有授权是否涵盖。

## 验收重点

- 一个包含实际删除区间的工程：源时间中的动效正确出现在剪辑后视频上，不继续使用原片长度与时码。
- 主预览和正式成片均包含同版 Remotion 动效，画幅、帧率、时长、透明度及字幕合成正确；最终音轨保留。
- 修改后旧版完整保留，新版哈希与审片证据不能复用；失效透明层、未知事件、映射错误及缺失合成证据均被拒绝。
- 旧工程无需迁移仍可播放和修改；不再强制新任务重复渲染 HyperFrames 与 Remotion 对照。
- 统一工作台只突出一个当前结果，修改与导出使用正确版本，字幕与成片 QC 门禁保留。
- 通过相关渲染、工具及版本回归验证、完整 `npm run verify`、类型检查和构建；桌面与手机实际浏览器检查通过。

## 技术依据

- 已安装运行时固定使用 Remotion 4.0.539，现有代码已采用 `renderMedia` 的 `prores`、`4444`、PNG 帧与 `yuva444p10le` 透明像素格式。
- 官方透明输出约定：[Rendering transparent videos](https://www.remotion.dev/docs/transparent-videos)、[ProRes](https://www.remotion.dev/docs/prores)。
- 继续按 `remotion-best-practices` 使用帧驱动动画和本地透明层输出，不采用不能保证离线渲染一致性的 CSS 动画。
